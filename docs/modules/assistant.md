# Module: assistant

**Gradle path:** `:assistant`.

## Responsibility
- Subtitle Engine: parse SRT/ASS, keep the current cue in sync with player time (`currentSubtitle`).
- `com.teachermovies.assistant.subtitles.SubtitleIndex(track: SubtitleTrack)`: `cueAt(positionMs): SubtitleCue?` binary-searches the cues sorted by `startMs` for the one with the greatest `startMs` that is `<= positionMs` (the same candidate wins when cues overlap, as ASS allows), then checks it still covers the half-open `[startMs, endMs)` range; `null` in a gap, before the first cue, after the last one, or for an empty track. `cueAtOrBefore(positionMs): SubtitleCue?` runs the same binary search without the end check: the cue containing the position or, in a gap or after the last cue, the last cue whose `startMs <= positionMs`; `null` only before the first cue or for an empty track.
- `com.teachermovies.assistant.SubtitleEngine(positionMs: Flow<Long>, scope: CoroutineScope)`: collects `positionMs` on `scope` for as long as it stays alive and exposes `val currentSubtitle: StateFlow<SubtitleCue?>`, resolved through a `SubtitleIndex` built from whatever `SubtitleTrack` `load(track: SubtitleTrack?)` last set (`load(null)` clears it back to `null`). `load` also re-resolves `currentSubtitle` immediately against the last known position, without waiting for the next `positionMs` emission. `StateFlow`'s conflation is what keeps `currentSubtitle` from re-emitting while the position moves within the same cue (or the same gap): only an actual cue change gets a new value. The real caller (#83) is `Player.positionMs`; tests drive it from a plain `MutableStateFlow<Long>`. The engine's third constructor parameter `maxGapMs: Long = 3_000` drives `cueForCapture(positionMs): SubtitleCue?`: the cue at that position, or the previous cue when it ended no more than `maxGapMs` before it (the viewer reacts after the line is over), else `null` (also while no track is loaded).
- `com.teachermovies.assistant.subtitles.SubtitleParsers.parse(file: File): ParseResult`: dispatches on the file name to the `.srt`/`.ass` parser that supports it and never lets an exception escape; `ParseResult` is `Parsed(track)`, `Unsupported(extension)` or `Malformed(reason)`, and a supported file that yields zero cues is `Malformed` too.
- `com.teachermovies.assistant.subtitles.SidecarSubtitles.findFor(mediaFile: File, language: String = "en"): File?`: the standalone subtitle file that belongs to a movie. It searches, case-insensitively, the media file's own directory and a `Subs` subdirectory of it (the layout most torrents ship), preferring `<base>.<language>.<ext>` over `<base>.<ext>` over any `*.<language>.<ext>`, then `.srt` over `.ass`, then the media's own directory over `Subs`, then the name, so the answer does not depend on the order the filesystem happens to list files in. `null` when nothing matches; a directory that does not exist contributes no candidates instead of throwing.
- `com.teachermovies.assistant.HiddenSubtitleController(player: Player, engine: SubtitleEngine, scope: CoroutineScope)`: hidden EN subtitle mode (VISION §7, "Mostrar subtítulos: No") -- the assistant reads the movie's English cues in sync with playback while the player draws nothing on screen. `start(mediaFile: File, language: String = "en"): HiddenModeResult` resolves the sidecar file with `SidecarSubtitles`, parses it with `SubtitleParsers`, hands the track to `engine.load` and calls `player.selectSubtitle(null)`, returning `HiddenModeResult.Started`; it returns `NoSubtitleFile` when no sidecar exists for that language and `Unreadable(reason)` when the file cannot be turned into cues, and both failures leave the player's own subtitle selection untouched and `active` false. `start` stops any previous session first.
- While `HiddenSubtitleController.active: StateFlow<Boolean>` is true, the controller collects `player.selectedSubtitleId` on its `scope` and calls `player.selectSubtitle(null)` again on every non-null value, so a default-track policy in `:player` can never turn the on-screen subtitles back on behind the assistant's back. `stop()` clears the engine's track (`load(null)`), cancels that re-assertion and sets `active` false; it deliberately does not re-enable any subtitle track -- whether the viewer wants on-screen subtitles back is the caller's decision. The `SubtitleEngine` it is given is expected to have been built over the same player's `positionMs`: that is what makes `currentSubtitle` follow playback while hidden mode is on.
- Hidden mode needs a standalone `.srt`/`.ass` file: cues embedded in the video container are not reachable through the `Player` interface, so a movie without a sidecar gets `NoSubtitleFile`.
- `com.teachermovies.assistant.LineCaptureController(player: Player, engine: SubtitleEngine, scope: CoroutineScope, preRollMs: Long = 300, tailMs: Long = 200)`: "what did they say?" (VISION §7). `capture(): CaptureResult` always calls `player.pause()` first, then resolves `player.positionMs.value` through `engine.cueForCapture`; with a cue it emits `CapturedLine(cue, capturedAtMs = that position)` on `captured: StateFlow<CapturedLine?>` and returns `CaptureResult.Captured`, otherwise it returns `NoLine` and changes nothing else (the player stays paused either way). `replay(): Boolean` returns `false` with nothing captured; otherwise it seeks to `max(0, cue.startMs - preRollMs)`, plays, sets `replaying: StateFlow<Boolean>` true and starts one watcher coroutine on `scope` that, once the position reaches `cue.endMs + tailMs` or the player state becomes `Ended`/`Error`, pauses, seeks back to `capturedAtMs` and sets `replaying` false. The capture survives a replay, so it can be replayed again; a `replay()` during a replay cancels the running watcher and restarts the fragment, so at most one watcher ever exists. `dismiss(resume: Boolean = true)` cancels any replay, clears `captured` and `replaying`, seeks back to `capturedAtMs` and plays only when `resume` (with `resume = false` the player is left paused there); with nothing captured it is a no-op. The remote-control keys and overlay that call it are #86.
- Remote-control actions: pause + capture current cue, replay original fragment, EN TTS, ES translation + TTS.
- Android `TextToSpeech` wrapper; `TranslationProvider` interface with swappable implementations (AI API optional, NOT on the MVP critical path).
- Speech (`com.teachermovies.assistant.speech`): `interface Speaker` with `state: StateFlow<SpeakerState>` (`Idle` / `Speaking(text, language)`), `availability: StateFlow<SpeakerAvailability?>` (`null` until `prepare()` has run once; then `Ready`, `MissingVoice(language)` or `EngineUnavailable`), `suspend fun prepare()`, `speak(text, language: SpeechLanguage): Boolean`, `stop()` and `shutdown()`. `SpeechLanguage` is `EN("en-US")` / `ES("es-ES")`. No Android or `android.speech.tts` type appears in the contract, so callers above this module compile against the interface only. `speak` returns `false` and leaves `state` at `Idle` unless `prepare()` returned `Ready` (so never for the language a `MissingVoice` reports), after `shutdown()`, and for text `SpeechRequests.isSpeakable` rejects (blank, or only punctuation/subtitle artefacts such as `-`, `...`, `♪`); it never throws. A new `speak` flushes whatever is being said. `stop()` silences the engine and sets `Idle`; `shutdown()` releases the engine and is idempotent, also before `prepare()`. A missing engine or voice degrades the feature to text only; installing voice data is out of scope.
- `SpeechRequests.utteranceId(seq)` gives a stable, unique utterance id per sequence number. `AndroidTextToSpeechSpeaker(context, timeoutMs = 5_000)` is the real implementation: `prepare()` waits for `TextToSpeech`'s `OnInitListener` (`EngineUnavailable` on `ERROR` or timeout), then checks `isLanguageAvailable` for each `SpeechLanguage` in order and reports the first missing one as `MissingVoice`; `speak` sets the utterance language and uses `QUEUE_FLUSH`, and an `UtteranceProgressListener` bridges `onStart` -> `Speaking` and `onDone`/`onError`/`onStop` -> `Idle` for the latest utterance only. Nothing in the speech package logs user text.
- `com.teachermovies.assistant.speech.fake.FakeSpeaker` (main source set, ADR-0003) is the default `Speaker` for every test above this module: `nextAvailability` sets what `prepare()` returns, `spoken` records every accepted `speak`, and `finishCurrentUtterance()` / `failCurrentUtterance()` drive `Speaking` back to `Idle`.
- Translation (`com.teachermovies.assistant.translation`): `interface TranslationProvider` with `val id: String` and `suspend fun translate(text: String, from: SpeechLanguage = EN, to: SpeechLanguage = ES): TranslationResult`, reusing `SpeechLanguage` from the speech package. `translate` never throws (cancellation aside): every failure is a `TranslationResult`. `sealed interface TranslationResult` has three members: `Translated(text, fromCache)`, `Offline` (a provider is configured but cannot be reached right now: the graceful-degradation case, a later attempt may succeed) and `Unavailable(reason)` (no provider, or the provider refused). Blank `text`, or `from == to`, is answered with `Translated(text.trim(), fromCache = true)` without reaching any backend (`TranslationRequests.shortcut`, which every implementation calls first).
- `object NullTranslationProvider` (`id = "none"`) returns `Unavailable("no translation provider configured")` for every real request; it is the app's default until a real provider is configured. No network implementation exists yet (ADR-0001 §6: not on the MVP critical path).
- `CachingTranslationProvider(delegate, maxEntries = 200)` (`id = delegate.id`) is an in-memory LRU decorator keyed by the trimmed, lower-cased (`Locale.ROOT`), whitespace-collapsed text plus both language tags. Only `Translated` is cached; `Offline` and `Unavailable` pass through uncached so a later call retries. A hit returns `Translated(cached, fromCache = true)` without calling the delegate; a miss returns the delegate's result with `fromCache = false`. Beyond `maxEntries` the least recently used entry is evicted. A `Mutex` (never a blocking lock) guards the cache and is held across the delegate call, so concurrent calls are serialised and two concurrent calls for the same line reach the delegate once. An exception escaping a misbehaving delegate becomes `Unavailable`. The cache is not persisted across restarts.
- `com.teachermovies.assistant.translation.fake.FakeTranslationProvider` (main source set, ADR-0003): a mutable `translations` map of canned answers (exact text key), `var delayMs` (virtual time under `runTest`), `var nextResult` that overrides the map once, and `requests: List<String>` recording every text that really reached it (shortcuts are not recorded); an unknown key is `Unavailable("no canned translation")`.

## Boundaries
- Depends on the `Player` interface, never on libVLC directly: `:assistant` has an `api` dependency on
  `:player` (a `Player` is a constructor parameter of `HiddenSubtitleController`, so whoever wires the
  assistant compiles against it) and uses only its public `com.teachermovies.player.api` package; no
  `org.videolan` type is referenced anywhere in the module, and tests drive it from
  `com.teachermovies.player.fake.FakePlayer`. Network translation must degrade gracefully when offline.

## Tests
JVM tests for SRT/ASS parsing, cue lookup by time, fragment boundaries; fake TTS/translation.
`SubtitleIndexTest` covers boundaries, gaps, overlaps and the empty track; `SubtitleEngineTest` drives
`SubtitleEngine` from a `MutableStateFlow<Long>` under `kotlinx-coroutines-test`'s `runTest`.
`SidecarSubtitlesTest` builds temporary directories to cover the discovery order, the `Subs` subdirectory,
case-insensitivity and the no-match and missing-directory cases; `HiddenSubtitleControllerTest` drives a
`FakePlayer` under `runTest` to cover subtitles forced off on start, re-assertion after an external
selection, cues following emitted positions, `NoSubtitleFile`, `Unreadable` and `stop`.
`FakeSpeakerTest` covers the unavailable engine, missing voice, blank and unspeakable text, the `spoken`
record, `Speaking` -> `Idle` transitions and idempotent `shutdown`; `SpeechRequestsTest` covers utterance
ids and the unspeakable-text rules. `AndroidTextToSpeechSpeaker` is not JVM-testable (manual check on a TV).
`FakeTranslationProviderTest` covers canned answers, `nextResult`, `delayMs`, the `requests` record, the
blank and `from == to` shortcuts and `NullTranslationProvider`; `CachingTranslationProviderTest` covers a
miss then a hit, hits across spacing/casing differences, the language pair in the key, `Offline` and
`Unavailable` not being cached, LRU eviction at `maxEntries`, two concurrent calls for the same text and a
throwing delegate.
