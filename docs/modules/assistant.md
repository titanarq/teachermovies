# Module: assistant

**Gradle path:** `:assistant`.

## Responsibility
- Subtitle Engine: parse SRT/ASS, keep the current cue in sync with player time (`currentSubtitle`).
- `com.teachermovies.assistant.subtitles.SubtitleIndex(track: SubtitleTrack)`: `cueAt(positionMs): SubtitleCue?` binary-searches the cues sorted by `startMs` for the one with the greatest `startMs` that is `<= positionMs` (the same candidate wins when cues overlap, as ASS allows), then checks it still covers the half-open `[startMs, endMs)` range; `null` in a gap, before the first cue, after the last one, or for an empty track. `cueAtOrBefore(positionMs): SubtitleCue?` runs the same binary search without the end check: the cue containing the position or, in a gap or after the last cue, the last cue whose `startMs <= positionMs`; `null` only before the first cue or for an empty track. `cueLinesBefore(cue, lines): SteppedCue?` (#339) steps `lines` positions back from `cue` in that same sorted list -- a direct index step, never a rescan -- clamped at the first cue, and reports in `SteppedCue.linesBack` the step actually taken, smaller than `lines` once the track runs out of lines to go back through; `null` for an empty track or a `cue` that is not part of it.
- `com.teachermovies.assistant.SubtitleEngine(positionMs: Flow<Long>, scope: CoroutineScope)`: collects `positionMs` on `scope` for as long as it stays alive and exposes `val currentSubtitle: StateFlow<SubtitleCue?>`, resolved through a `SubtitleIndex` built from whatever `SubtitleTrack` `load(track: SubtitleTrack?)` last set (`load(null)` clears it back to `null`). `load` also re-resolves `currentSubtitle` immediately against the last known position, without waiting for the next `positionMs` emission. `StateFlow`'s conflation is what keeps `currentSubtitle` from re-emitting while the position moves within the same cue (or the same gap): only an actual cue change gets a new value. The real caller (#83) is `Player.positionMs`; tests drive it from a plain `MutableStateFlow<Long>`. The engine's third constructor parameter `maxGapMs: Long = 3_000` drives `cueForCapture(positionMs): SubtitleCue?`: the cue at that position, or the previous cue when it ended no more than `maxGapMs` before it (the viewer reacts after the line is over), else `null` (also while no track is loaded). `cueLinesBefore(cue, lines): SteppedCue?` (#339) delegates to the same index and is `null` while no track is loaded or for a cue that is not part of the loaded one; it is what `LineCaptureController` walks back through.
- `com.teachermovies.assistant.subtitles.SubtitleParsers.parse(file: File): ParseResult`: dispatches on the file name to the `.srt`/`.ass` parser that supports it and never lets an exception escape; `ParseResult` is `Parsed(track)`, `Unsupported(extension)` or `Malformed(reason)`, and a supported file that yields zero cues is `Malformed` too.
- `com.teachermovies.assistant.subtitles.SidecarSubtitles.findFor(mediaFile: File, language: String = "en"): File?`: the standalone subtitle file that belongs to a movie. It searches, case-insensitively, the media file's own directory and a `Subs` subdirectory of it (the layout most torrents ship), preferring `<base>.<language>.<ext>` over `<base>.<ext>` over any `*.<language>.<ext>`, then `.srt` over `.ass`, then the media's own directory over `Subs`, then the name, so the answer does not depend on the order the filesystem happens to list files in. `null` when nothing matches; a directory that does not exist contributes no candidates instead of throwing. A file whose name carries `.opensubtitles.` is never a candidate, whatever its language: an automatic download is hidden mode's last resort (`DownloadedSubtitles` below), not its first, and the Spanish one the bridge fetches for every movie must never be read as the English track (#284).
- `com.teachermovies.assistant.subtitles.DownloadedSubtitles.findFor(mediaFile: File, language: String = "en"): File?`: the subtitle file the laptop bridge downloaded from OpenSubtitles for a movie (ADR-0005 §5, #284), `<base>.<language>.opensubtitles.<ext>` in the movie's own directory or its `subs/`. `MARKER` (`"opensubtitles"`) is the marker `:bridge-protocol`'s `BridgeSubtitleProtocol.fileName` puts in that name, spelled again here because a feature module does not depend on another one; `isDownloadedName(name)` (lower-cased) is the one predicate both lookups use, `SidecarSubtitles` skipping what it accepts. The search covers the same directories as `SidecarSubtitles`, is case-insensitive and never throws, and ranks `<base>.<language>.<marker>.<ext>` first, then the same pattern on any other base (what a download made for an earlier main file leaves behind), then `.srt` over `.ass`, then the media's own directory over `Subs`, then the name. Only the language part of the name -- the token just before the marker, matched exactly -- may be `language`, so `movie.es.opensubtitles.srt` is no answer for `"en"`, not even when the movie's own name starts with those letters (`entangled.es.opensubtitles.srt`).
- `com.teachermovies.assistant.HiddenSubtitleController(player: Player, engine: SubtitleEngine, scope: CoroutineScope, cacheDir: File)`: hidden EN subtitle mode (VISION §7, "Mostrar subtítulos: No") -- the assistant reads the movie's English cues in sync with playback while the player draws nothing on screen. `suspend start(mediaFile: File, language: String = "en", viewerSubtitleId: String? = null): HiddenModeResult` resolves the cues from one of three sources (`enum class SubtitleSource { SIDECAR, EMBEDDED, DOWNLOADED }`), parses them with `SubtitleParsers`, hands the track to `engine.load` and calls `player.selectSubtitle(null)`, returning `HiddenModeResult.Started(source)`. It returns `NoSubtitleFile` when none of the three exists for that language and `Unreadable(reason)` when the cues cannot be obtained or parsed; every failure leaves the player's own subtitle selection untouched and `active` false. `start` stops any previous session first.
- While `HiddenSubtitleController.active: StateFlow<Boolean>` is true, the controller collects `player.selectedSubtitleId` on its `scope` and calls `player.selectSubtitle(null)` again on every non-null value, so a default-track policy in `:player` can never turn the on-screen subtitles back on behind the assistant's back. The viewer's own choice wins (#227): `selectByViewer(id: String?)` -- what the tracks panel calls -- cancels that re-assertion until the next `start` (the next movie) and then selects `id` on the player; `active` stays true and the engine keeps its cues, so capture keeps working. Only selections made directly on the player (policy) are still reverted. The choice persisted from an earlier session counts as a viewer choice too (#248): `PlayerViewModel` passes the library row's `subtitleTrackId` as `viewerSubtitleId`, and `start` neither turns that track off (when it is already selected) nor reverts it later, so `PlaybackSession`'s `TrackPolicy` can re-apply it on reopen whichever runs first; any other non-null selection is reverted **to that track** when the player lists it (otherwise to off). Reverting to the stored track rather than to off is what keeps it on a reopen without a process restart: while libVLC starts the media it briefly reads back its own default subtitle after the session asked for the stored one, and since libVLC applies the last request, turning that default off also cancelled the stored track, which the session then saved as off (emulator, logcat tag `TmTracks`). `stop()` clears the engine's track (`load(null)`), cancels that re-assertion and sets `active` false; it deliberately does not re-enable any subtitle track -- whether the viewer wants on-screen subtitles back is the caller's decision. The `SubtitleEngine` it is given is expected to have been built over the same player's `positionMs`: that is what makes `currentSubtitle` follow playback while hidden mode is on.
- Subtitle sources, in fallback order: (1) `SIDECAR`, the standalone `.srt`/`.ass` file `SidecarSubtitles.findFor` returns -- it always wins; (2) only when there is none, `EMBEDDED`: the text subtitle track in the movie's own container that `com.teachermovies.assistant.subtitles.EmbeddedSubtitleTracks.pick(player.subtitleTracks.value, language)` chooses (case-insensitive ranking: `Track.language` equal to the code, then starting with it so `eng` matches `en`, then `Track.name` containing `[en]` or the language's English name `english`; ties by list order; `null` when nothing matches). The chosen track is written by `Player.extractTextSubtitle` into `<cacheDir>/subtitles/<media base name>.<sanitised track id>.<srt|ass>` (created if missing); an existing non-empty cache file is parsed directly without extracting again, and nothing (not even `stop()`) deletes the cache. `extractTextSubtitle` returning `Failed`, `NotTextBased` (image-based PGS/VobSub tracks) or `TrackNotFound`, or the extracted file failing to parse, is `Unreadable` with a reason naming which. `AppContainer` passes `application.cacheDir`. libVLC publishes a media's tracks only once it has parsed it, which can be after `PlaybackSession.open` returns: when `player.subtitleTracks.value` is still empty, `start` suspends (no blocking) until `player.subtitleTracks` publishes a non-empty list, for at most `HiddenSubtitleController.TRACKS_TIMEOUT_MS` (3 000 ms), and applies `EmbeddedSubtitleTracks.pick` to that first non-empty list; the timeout elapsing rules `EMBEDDED` out and `start` goes on to (3). A list already known when `start` runs is used at once, so tracks without an English one go straight to (3), without waiting. A `stop()` while `start` is still waiting (or extracting) wins: that `start` returns `NoSubtitleFile` at once and activates nothing, so a viewer leaving the player right after opening is not held up by the wait -- it does not even look for (3). (3) only when the movie has neither of the two, `DOWNLOADED` (#284): the file `DownloadedSubtitles.findFor` returns for that language, parsed like a sidecar and never the Spanish download the bridge leaves next to every movie. Being the last resort, it is looked for only once the embedded track is ruled out, so a movie whose only English subtitle is a downloaded one spends up to `TRACKS_TIMEOUT_MS` waiting for libVLC's tracks before hidden mode starts.
- `com.teachermovies.assistant.subtitles.OpenSubtitlesHash.of(file: File): MovieHashResult`: the OpenSubtitles moviehash of a completed movie (ADR-0005 §5), which is what lets the laptop bridge look subtitles up by hash instead of by name alone. The hash is the file's size in bytes plus the sums of its first and last 64 KiB read as little-endian 64-bit words, rendered as 16 lower-case hex digits; only those two blocks are read, so hashing a multi-gigabyte movie costs 128 KiB of I/O whatever its size. `MovieHashResult` is `Computed(hash, fileSizeBytes)`, `TooSmall(fileSizeBytes)` for a file under 128 KiB -- its two blocks would overlap, and OpenSubtitles skips such files -- or `Unreadable(reason)` for a path that is not a readable file (missing, a directory, an I/O failure); no exception escapes `of`.
- Spanish alignment (`com.teachermovies.assistant.alignment`, ADR-0005 §6, #283): `SubtitleAligner().align(english: SubtitleTrack, spanish: SubtitleTrack): AlignmentFit` finds, from cue timing alone, how a Spanish track lines up with the English one: `esMs = enMs * frameRateScale + offsetMs`, the same convention as `:core-model`'s `SubtitleAlignment`. For each of three frame-rate scales (`1`, `25/23.976`, `23.976/25`), every pair of cue starts closer than 15 s votes in an offset histogram of 100 ms bins; the five strongest (3-bin smoothed) peaks and their neighbouring bins are scored. An English cue matches a Spanish cue when their time ranges overlap by at least 30 % (intersection over union, `SubtitleAligner.MIN_OVERLAP`); each Spanish cue matches at most once, in English order; two adjacent English cues that both match nothing alone may be joined against one Spanish cue (never more than 2). The candidate with the largest total overlap wins (ties: scale in the order above, then the smaller offset). `AlignmentFit.qualityScore` is chance-corrected: with `m` the Spanish cues matched over the smaller of the two cue counts (so a translation missing lines is not penalised) and `c` the median of that share at eight decoy offsets 5-23 s from the winner (what unrelated, equally dense timelines reach), `quality = (m - c) / (1 - c)` clamped to 0..1; `isGood` is `qualityScore >= SubtitleAligner.GOOD_QUALITY` (0.6). An empty track, or no match at all, is `AlignmentFit(0, 1.0, 0.0)`. On synthetic tracks an unrelated Spanish track scores about 0.03-0.22, and a correctly aligned one missing a third of its lines, with 500 ms of timing noise, 0.97-1.0.
- `SpanishLineLookup(repository: SubtitleAlignmentRepository, nowMs: () -> Long, aligner = SubtitleAligner(), dispatcher = Dispatchers.Default)`: `suspend lineFor(torrentId, english: SubtitleTrack, cue: SubtitleCue, candidates: List<SpanishSubtitleCandidate>): SpanishLineResult` returns the Spanish line for a captured English cue. A `SpanishSubtitleCandidate(source, path, track)` is tried in source order `SIDECAR`, then `EMBEDDED`, then `DOWNLOADED` (`enum class SpanishSubtitleSource`; list order within one source). `alignmentFor(torrentId, english, candidate): SubtitleAlignment` reads the alignment cached in Room (#274) by (torrent, `path`) or, on a miss, aligns on `dispatcher` and saves it with `computedAtEpochMs = nowMs()`; a cached row is never recomputed. A candidate under 0.6 is skipped; in the first good one the cue is mapped onto the Spanish timeline and the Spanish cue overlapping it most (at least 30 %) wins; when the cue alone matches nothing it is joined with the previous or next English cue, only one that matches nothing alone either (whichever overlaps more). A good candidate without a match falls through to the next good one. The result is `Found(SpanishLine(text, cue, source, subtitlePath, qualityScore))`, `NoGoodAlignment` (no candidate, or none good enough) or `NoMatchingLine` (a good alignment, but nothing under this cue). What LEFT shows without a line (the bridge translation) is #288.
- `com.teachermovies.assistant.LineCaptureController(player: Player, engine: SubtitleEngine, scope: CoroutineScope, preRollMs: Long = 300, tailMs: Long = 200, clock: () -> Long = { System.currentTimeMillis() })`: "what did they say?" (VISION §7). `capture(): CaptureResult` always calls `player.pause()` first, then resolves `player.positionMs.value` through `engine.cueForCapture`; with a cue it emits `CapturedLine(cue, capturedAtMs = that position)` on `captured: StateFlow<CapturedLine?>` and returns `CaptureResult.Captured`, otherwise it returns `NoLine` and changes nothing else (the player stays paused either way). `replay(): Boolean` returns `false` with nothing captured. Calls arriving no more than `LineCaptureController.REPLAY_BACK_WINDOW_MS` (1 500 ms, measured with `clock`) after the previous one form a run, whose first member is the first `replay()` after a `capture()`: the Nth call of a run (N = 1, 2, 3, ...) replays the cue N - 1 lines before the captured one, resolved through `engine.cueLinesBefore`, so OK pressed in a row walks back through the track line by line (#339) instead of repeating the same line, and once that walk reaches the track's first cue further presses keep replaying it. `linesBack: StateFlow<Int>` says how many lines back the cue being replayed is -- 0 for the captured line itself, and less than N - 1 while the walk is clamped -- and `capture()` and `dismiss()` reset it to 0. Whatever the target cue, it seeks to `max(0, cue.startMs - preRollMs)`, plays, sets `replaying: StateFlow<Boolean>` true and starts one watcher coroutine on `scope` that, once the position reaches that cue's `endMs + tailMs` or the player state becomes `Ended`/`Error`, pauses, seeks back to `capturedAtMs` and sets `replaying` false. The capture survives a replay, so it can be replayed again; a `replay()` during a replay cancels the running watcher and restarts the fragment, so at most one watcher ever exists. `dismiss(resume: Boolean = true)` cancels any replay, clears `captured` and `replaying`, seeks back to `capturedAtMs` and plays only when `resume` (with `resume = false` the player is left paused there); with nothing captured it is a no-op. The remote-control keys and overlay that call it are #86.
- `com.teachermovies.assistant.PhraseRewindController(player: Player, engine: SubtitleEngine, spanish: SpanishTextSource, scope: CoroutineScope, preRollMs: Long = 300, clock: () -> Long = { System.currentTimeMillis() })`: the phrase rewind (#343, ADR-0005's D-pad interaction model) -- N presses in a row go back N subtitle phrases, show the line being replayed, and put the subtitle state back once playback returns to where the run started. `press(language: SubtitleDisplay)` (`enum class SubtitleDisplay { OFF, ENGLISH, SPANISH }`, where `OFF` is what a run restores and not a press the remote can make, so it is ignored) opens or extends a group: presses whose gap to the previous one, measured with `clock`, is under `PhraseRewindController.REWIND_GROUP_WINDOW_MS` (1 500 ms) are one group of N presses whose language is the one of its last press. Nothing is sought while presses keep arriving; once the window has closed with no further press, one coroutine on `scope` resolves the cue at (or just before) the position of the group's first press through `engine.cueForCapture`, steps N - 1 phrases back through `engine.cueLinesBefore` -- clamped at the track's first cue -- and seeks to `max(0, cue.startMs - preRollMs)` and plays, from a playing or a paused player alike. A first press whose position resolves to no cue (no track loaded, or a gap longer than the engine's `maxGapMs`) seeks nothing and ends the run: a language on screen with no line under it is worse than none. `display: StateFlow<SubtitleDisplay>` is the group's language from its first press on, and `displayText: StateFlow<String?>` the line of that language at the current position -- English from the track `engine` has loaded, Spanish from `SpanishTextSource`, `null` when the source of the chosen language has nothing there -- both published by the one coroutine that also watches for the run's end, so the controller starts no other coroutine and `cancel()` leaves none alive. That end is the run's return point, the position of the first press of the *run*: reaching it restores `display` to whatever it was before the run (`OFF` before a first one, a later group never re-saving it) and stops tracking. A group pressed again while rewound, before that point, rewinds from where playback is but keeps the original return point and the original saved display. The player ending or erroring, and `cancel()`, drop the run and restore the same way, and leave the player itself alone.
- `fun interface SpanishTextSource` (`textAt(positionMs): String?`) is the Spanish line spoken at a playback position, the seam the phrase rewind draws its Spanish through: the timeline behind it is the Spanish-subtitle-text issue's, so `:assistant` programs against this one function. `com.teachermovies.assistant.fake.FakeSpanishTextSource(lines)` (main source set, ADR-0003) is what every test above this module uses: canned `SubtitleCue`s answered under the same half-open `[startMs, endMs)` rule (`null` in a gap, before the first line and after the last one), with every position asked about recorded in `queries`.
- Remote-control actions: pause + capture current cue, replay original fragment, EN TTS, ES translation + TTS.
- Android `TextToSpeech` wrapper; `TranslationProvider` interface with swappable implementations (AI API optional, NOT on the MVP critical path).
- Speech (`com.teachermovies.assistant.speech`): `interface Speaker` with `state: StateFlow<SpeakerState>` (`Idle` / `Speaking(text, language)`), `availability: StateFlow<SpeakerAvailability?>` (`null` until `prepare()` has run once; then `Ready`, `MissingVoice(languages: Set<SpeechLanguage>)` (never empty; `setOf(EN, ES)` when every voice is missing, not `EngineUnavailable`) or `EngineUnavailable`), `suspend fun prepare()`, `speak(text, language: SpeechLanguage): Boolean`, `stop()` and `shutdown()`. `SpeechLanguage` is `EN("en-US")` / `ES("es-ES")`. No Android or `android.speech.tts` type appears in the contract, so callers above this module compile against the interface only. Readiness is per language, because EN TTS and ES translation + TTS are independent actions (VISION §7): `speak` accepts a language when `prepare()` returned `Ready` or a `MissingVoice` whose `languages` does not contain it (`SpeechRequests.allows(availability, language)`), so a missing ES voice never silences EN and vice versa. It returns `false` and leaves `state` at `Idle` for a language `MissingVoice` lists, for `EngineUnavailable`, before `prepare()`, after `shutdown()`, and for text `SpeechRequests.isSpeakable` rejects (blank, or only punctuation/subtitle artefacts such as `-`, `...`, `♪`); it never throws. A new `speak` flushes whatever is being said. `stop()` silences the engine and sets `Idle`; `shutdown()` releases the engine and is idempotent, also before `prepare()`. A missing engine degrades speech to text only; a missing voice degrades only its language; installing voice data is out of scope.
- `SpeechRequests.utteranceId(seq)` gives a stable, unique utterance id per sequence number. `AndroidTextToSpeechSpeaker(context, timeoutMs = 5_000)` is the real implementation: `prepare()` waits for `TextToSpeech`'s `OnInitListener` (`EngineUnavailable` on `ERROR` or timeout), then checks `isLanguageAvailable` for every `SpeechLanguage` (no early return) and reports the full missing set as `MissingVoice(languages)`; `FakeSpeaker` applies the same rule from `nextAvailability`; `speak` sets the utterance language and uses `QUEUE_FLUSH`, and an `UtteranceProgressListener` bridges `onStart` -> `Speaking` and `onDone`/`onError`/`onStop` -> `Idle` for the latest utterance only. Nothing in the speech package logs user text.
- `com.teachermovies.assistant.speech.SpokenOutputSettings(englishLine = false, spanishLine = false, explanations = false)`: which of the assistant's three spoken answers the learner has turned back on (#294). ADR-0005 §10 defers TTS, so every flag defaults to off and nothing is spoken aloud until one is set; the flags are independent, because wanting the Spanish line says nothing about wanting the English one too. `AssistantSpeechController` reads them at the moment of speaking, never at construction, so a change applies from the next line on without reopening the player, and they gate only the voice: the Spanish line and the explanation are shown on screen whatever the setting says. The type lives here, in `:assistant`; persisting it (a DataStore key plus three Configuración switches, `:core-model`/`:app-tv`) is the wiring's job, and whoever does it hands the controller a `StateFlow<SpokenOutputSettings>` mapped from `SettingsRepository.settings` the way `AppContainer` already maps `downloadVolumeId`.
- `com.teachermovies.assistant.speech.fake.FakeSpeaker` (main source set, ADR-0003) is the default `Speaker` for every test above this module: `nextAvailability` sets what `prepare()` returns, `spoken` records every accepted `speak`, and `finishCurrentUtterance()` / `failCurrentUtterance()` drive `Speaking` back to `Idle`.
- Translation (`com.teachermovies.assistant.translation`): `interface TranslationProvider` with `val id: String` and `suspend fun translate(text: String, from: SpeechLanguage = EN, to: SpeechLanguage = ES): TranslationResult`, reusing `SpeechLanguage` from the speech package. `translate` never throws (cancellation aside): every failure is a `TranslationResult`. `sealed interface TranslationResult` has three members: `Translated(text, fromCache)`, `Offline` (a provider is configured but cannot be reached right now: the graceful-degradation case, a later attempt may succeed) and `Unavailable(reason)` (no provider, or the provider refused). Blank `text`, or `from == to`, is answered with `Translated(text.trim(), fromCache = true)` without reaching any backend (`TranslationRequests.shortcut`, which every implementation calls first).
- `object NullTranslationProvider` (`id = "none"`) returns `Unavailable("no translation provider configured")` for every real request; it is the app's default until a real provider is configured (ADR-0001 §6: translation is not on the MVP critical path).
- **Dormant (#290, ADR-0005 §9): not wired into the app.** `AppContainer` translates through `BridgeTranslationProvider` only, the Configuración field is gone (#289) and a stored key is cleared on upgrade (`:core-model`). The class below, `AnthropicApiConfigSource`, their tests and the `libs.anthropic.java` dependency stay in the tree, kept for a future extension -- do not delete them. As written, `AnthropicTranslationProvider(config: AnthropicApiConfigSource)` (`id = "anthropic"`, post-MVP) translates EN -> ES through Claude Sonnet 5 (`claude-sonnet-5`) with the official Anthropic Java SDK (`libs.anthropic.java`): one request per line, extended thinking disabled, `max_tokens = 256`, a fixed system prompt ("translate this English subtitle line to natural Spanish, reply with the translation only") and the line as the only user message; the trimmed reply is `Translated(text, fromCache = false)`, a blank one `Unavailable("empty translation")`. **The subtitle text is sent to Anthropic's API.** The API key is typed by the user in the Configuración screen and stored in DataStore (`:core-model`; the field and its key are a separate issue), and reaches the provider only through `fun interface AnthropicApiConfigSource { suspend fun apiKey(): String? }`, read on every request; a missing/blank key is `Unavailable("no translation provider configured")` without any connection. The key is never logged (SDK logging off) and never appears in a result. Failures map through an internal sealed `TranslationError`: connection refused / unknown host / no route / timeouts / other I/O -> `Offline`; 401/403 -> `Unavailable("authentication rejected")`; 429 -> `Unavailable("rate limited")`; other non-2xx -> `Unavailable("api error <code>")`; an unreadable body -> `Unavailable("malformed response")`; ES -> EN -> `Unavailable("unsupported language pair")`. Were it wired again, `CachingTranslationProvider` would go in front of it.
- `CachingTranslationProvider(delegate, maxEntries = 200)` (`id = delegate.id`) is an in-memory LRU decorator keyed by the trimmed, lower-cased (`Locale.ROOT`), whitespace-collapsed text plus both language tags. Only `Translated` is cached; `Offline` and `Unavailable` pass through uncached so a later call retries. A hit returns `Translated(cached, fromCache = true)` without calling the delegate; a miss returns the delegate's result with `fromCache = false`. Beyond `maxEntries` the least recently used entry is evicted. A `Mutex` (never a blocking lock) guards the cache and is held across the delegate call, so concurrent calls are serialised and two concurrent calls for the same line reach the delegate once. An exception escaping a misbehaving delegate becomes `Unavailable`. The cache is not persisted across restarts.
- `BridgeTranslateGateway` (`fun interface`, `suspend translate(text, from, to, timeout): BridgeTranslateOutcome`) is `:assistant`'s seam to the laptop bridge's job hub (ADR-0005 §2, #275). The hub itself lives in `:http-server` and `:bridge-protocol`, which a feature module must not depend on, so whoever wires the assistant adapts it to this one function; an implementation never throws (cancellation aside) and a hub that cannot even queue the job says so with an outcome. `sealed interface BridgeTranslateOutcome` keeps the hub's own names -- `Done(translation)`, `NoBridge`, `TimedOut`, `Disconnected`, `BridgeError(reason)` -- so the adapter is a `when` with no logic in it.
- `BridgeTranslationProvider(gateway: BridgeTranslateGateway, timeout: Duration = TIMEOUT)` (`id = "bridge"`) has one line translated on the laptop, by Claude Code on the household's own subscription (ADR-0005 §1/§3): the TV runs no AI call itself and stores no API key (the API-key provider this replaces is unwired by #290, its code kept dormant). Every outcome becomes a `TranslationResult`, so `translate` still never throws, and the split is the one the viewer feels: `NoBridge` (no laptop paired, or its bridge is not running) -> `Unavailable("no bridge connected")`, because asking again right now would answer the same; `TimedOut` and `Disconnected` -> `Offline`, the "the laptop may answer next time" case a later attempt retries; `BridgeError(reason)` -> `Unavailable("bridge error: <reason>")`; `Done` with nothing but whitespace -> `Unavailable("empty translation")`; `Done(text)` -> `Translated(text.trim(), fromCache = false)`. `TIMEOUT` is 15 s -- the budget the direct Anthropic call had -- and is passed to the gateway with every job. A gateway that throws anyway is `Unavailable("bridge error: <ClassName>")`, never an exception. The reasons are for logs: `AssistantSpeechController` maps any `Unavailable` to `Failed(UNAVAILABLE)` and the panel shows "Traducción no disponible" (ADR-0005 §6).
- `PersistentCachingTranslationProvider(delegate, cache: TranslationCacheRepository, clock: () -> Long = { System.currentTimeMillis() })` (`id = delegate.id`) is the Room-backed cache in front of a provider (#287 over #274's `translation_cache`), so answers survive a restart and are bounded by `CachePruningPolicy` rather than by an entry count. ADR-0005 §8: only `Translated` is stored, never an error state -- `Offline` and `Unavailable` pass through, store nothing and are retried on the next call, so a line the laptop could not answer is never remembered as untranslatable. The table is keyed by the normalized English source text and its answer column is `translationEs`, so only EN -> ES goes through it: any other pair reaches the delegate directly, is neither read nor written, and cannot shadow a row of the one direction the household watches. Keys keep their case (the repository normalizes whitespace only), unlike `CachingTranslationProvider`, which folds case too. A hit returns `Translated(cached, fromCache = true)` without calling the delegate, a miss returns the delegate's own result with `fromCache = false`, and `clock` supplies the `now` both repository methods take. The cache is an optimisation, so a repository that fails (Room I/O on a TV) cannot break the "never throws" contract: a read that throws is a miss, a write that throws costs one more bridge job later, and either way the viewer still gets the translation; an exception escaping the delegate becomes `Unavailable` as in `CachingTranslationProvider`. Wiring composes them `CachingTranslationProvider(PersistentCachingTranslationProvider(BridgeTranslationProvider(gateway), cache))`: the in-memory LRU absorbs a line repeated inside one session and serialises concurrent ones, the Room one survives the app. The wiring itself is #288/#289's.
- `com.teachermovies.assistant.translation.fake.FakeTranslationProvider` (main source set, ADR-0003): a mutable `translations` map of canned answers (exact text key), `var delayMs` (virtual time under `runTest`), `var nextResult` that overrides the map once, and `requests: List<String>` recording every text that really reached it (shortcuts are not recorded); an unknown key is `Unavailable("no canned translation")`.
- `com.teachermovies.assistant.translation.fake.FakeBridgeTranslateGateway` (main source set, ADR-0003) stands in for #275's job hub in every test above this module until the real hub is wired: canned `Done` answers from a `translations` map keyed by the exact text, `var nextOutcome` overriding the next call once, `BridgeError("no canned translation")` for an unknown text, and `requests: List<Request>` recording each job's text, direction and timeout. It applies no shortcut rule: the provider under test owns that, and whatever reaches a real hub is a job.
- `com.teachermovies.assistant.AssistantSpeechController(speaker: Speaker, translations: TranslationProvider, scope: CoroutineScope, spokenOutput: StateFlow<SpokenOutputSettings> = a flow of the all-off default)`: the three spoken answers for a `CapturedLine` (VISION §7): say it again in English, show plus say its Spanish translation, and say its explanation. It works only through `Speaker`, `TranslationProvider` and that settings flow (no Android, `TextToSpeech` or `org.videolan` type). Every utterance goes through one private `say(text, language, enabled)` which returns `false` without touching the engine when the `SpokenOutputSettings` flag for that answer is off, and then applies the per-language availability rule it always applied; so a `false` from `speakOriginal`, `speakTranslation` or `speakExplanation` means "off by setting" *or* "no voice for it", and a caller that has to tell the two apart reads the same flow it passed in. `prepare()` is deliberately **not** gated -- it initialises the engine whatever the setting says, so turning an answer on mid-session speaks from the next line instead of waiting for the player to reopen. The default parameter is the all-off value, which is what makes ADR-0005 §10 ("nothing is spoken aloud") hold for any caller that has not wired the setting yet. `state: StateFlow<AssistantSpeechState>` is `AssistantSpeechState(speaking = false, translation: TranslationUiState = Idle, speechAvailable: Set<SpeechLanguage> = every SpeechLanguage)`; `TranslationUiState` is `Idle` / `Loading` / `Ready(text)` / `Failed(reason: TranslationFailure)` with `TranslationFailure` `OFFLINE` / `UNAVAILABLE`. `suspend prepare()` calls `Speaker.prepare()` once (later calls do not touch the engine) and sets `speechAvailable` per language: `Ready` -> every language, `MissingVoice(languages)` -> every language except `languages`, `EngineUnavailable` (or a throwing engine) -> none; it never throws. `speakOriginal(line)` speaks `line.cue.text` in `EN`, gated by `englishLine`, and returns what `Speaker.speak` returned; after an accepted utterance `speaking` mirrors `Speaker.state` being `Speaking`. `translate(line)` sets `Loading` and runs **one** coroutine on `scope` calling `translations.translate(line.cue.text)`: `Translated` -> `Ready(text)`, `Offline` -> `Failed(OFFLINE)`, `Unavailable` (or an exception escaping a misbehaving provider) -> `Failed(UNAVAILABLE)`. The same line while `Loading` or `Ready` does not reach the provider again (after `Failed` it is retried); a different line cancels the in-flight call, clears the previous result and starts over, so at most one translation coroutine ever exists and a stale result never overwrites the new line. `speakTranslation()` returns `false` and does nothing unless `translation` is `Ready` and `spanishLine` is on, else speaks it in `ES`. `translateAndSpeak(line)` translates (reusing a `Ready` or in-flight result for the same line) and speaks the result in Spanish as soon as it arrives, reading `spanishLine` at that moment -- so with the flag off it is `translate`, and the Spanish line is read rather than heard; on `Failed` it speaks nothing and leaves the failure in the state. `speakExplanation(text)` says the explanation the screen already shows (ADR-0005 §7, produced by the bridge, not by this controller) in `ES` when `explanations` is on, and returns `false` without touching the engine otherwise. `reset()` calls `Speaker.stop()`, cancels the translation and the `speaking` mirror (no coroutine it started survives) and restores the defaults except `speechAvailable`.
- Degradation, per language (EN and ES are independent, VISION §7): with `EN` not in `speechAvailable`, `speakOriginal` returns `false` immediately and changes nothing else; with `ES` not in it, `speakTranslation` and the speech half of `translateAndSpeak` do the same. Two independent gates decide whether an answer is heard -- the learner's `SpokenOutputSettings` flag for that answer, and the voice availability for its language -- and either one saying no leaves the text on screen untouched, so the assistant always degrades to reading; a failed translation is shown as `Failed(OFFLINE)` (retry later) or `Failed(UNAVAILABLE)`. A caller that renders a `false` as "Voz no disponible" owes the learner the distinction (#294): an answer turned off in Configuración is a choice, not a missing voice, and is told apart by reading the same settings flow the controller was given. Caching is the `CachingTranslationProvider` composed around the provider at wiring time, not the controller's job; the remote keys, overlay and `AppContainer` construction live in `:app-tv`.
- Explanations (`com.teachermovies.assistant.explanation`, ADR-0005 §7, #292) -- RIGHT = "Explicar": `ExplanationContext(title, line, before, after, spanishLine)` is the explain job's payload one to one (#275's `BridgeJob.Explain`). `ExplanationContext.of(track, cue, title, spanishLine)` builds it from the captured cue: the nearest non-blank cues of its track, at most `MAX_BEFORE = 3` before and `MAX_AFTER = 2` after (oldest first), each starting at most `WINDOW_MS = 20_000` from the captured cue's start; every line trimmed, inner line breaks joined with a space and clipped to the hub's 500-char line limit; a blank title or Spanish line is null; a cue not in the track (matched by `index`) gets no neighbours. The caller resolves `spanishLine` (e.g. through `SpanishLineLookup`).
- `BridgeExplainGateway` (`fun interface`, `suspend explain(context, timeout): BridgeExplainOutcome` = `Done(document)` / `NoBridge` / `TimedOut` / `Disconnected` / `BridgeError(reason)`) is the seam to #275's hub, adapted by whoever wires the assistant (the hub's `Replaced` and `Rejected` become `BridgeError`). `Explanation.parse(document)` reads #291's reply `{"resumen", "puntos": [{"expresion", "explicacion"}], "diferencia_subtitulo"}` plus an optional `promptVersion` (or `prompt_version`) tag into `Explanation(summary, points, subtitleNote, promptVersion)`: tolerant (malformed points dropped, at most three kept, a blank note null) but null for anything without a non-blank `resumen`.
- `LineExplainer(gateway, cache: ExplanationCacheRepository, clock, timeout = 30 s, initialPromptVersion = PROMPT_VERSION = "explain-v1")`: `suspend explain(context): ExplanationResult` (`Explained(explanation, fromCache)` / `Offline` for `TimedOut`/`Disconnected` / `Unavailable(reason)` for no bridge, a bridge error, an unusable reply, a blank line or a throwing gateway; never throws). It looks `explanation_cache` up by (title, line, prompt version) first and stores only a parsed success, verbatim; the prompt version is the one the bridge last tagged a reply with, `initialPromptVersion` until then, and a tagged reply is stored under its tag -- so a changed bridge prompt never serves an older prompt's row, and bumping `PROMPT_VERSION` with the prompt retires old rows even before the first reply after a restart. A context without a title is never cached. A cache that throws is a miss / an ignored write; a stored row that no longer parses is a miss that the new answer replaces.
- `ExplanationController(explainer, scope)`: `state: StateFlow<ExplanationUiState>` = `Idle` / `Thinking(line)` / `Shown(line, explanation, fromCache)` / `Unavailable(line, retryable, reason)` (`retryable` for `Offline`; `reason` for logs only), rendered by #293. `explain(context)` cancels the request before it and sends the new one only once the old one has finished cancelling, so at most one explanation request is ever in flight; a late answer for a line the learner left is dropped; asking again for the line already on its way sends nothing. `dismiss()` cancels and returns to `Idle`. Nothing is asked except by `explain` (no prefetch) and nothing is spoken (no speech dependency; no TTS). `fake.FakeBridgeExplainGateway` (main source set, ADR-0003): canned `documents` by exact line, `nextOutcome`, `delayMs`, `requests` and `maxInFlight`.

## Boundaries
- Depends on the `Player` interface, never on libVLC directly: `:assistant` has an `api` dependency on
  `:player` (a `Player` is a constructor parameter of `HiddenSubtitleController`, so whoever wires the
  assistant compiles against it) and uses only its public `com.teachermovies.player.api` package; no
  `org.videolan` type is referenced anywhere in the module, and tests drive it from
  `com.teachermovies.player.fake.FakePlayer`. Network translation must degrade gracefully when offline.
- Depends on `:core-model` through its repository interfaces only (`com.teachermovies.core.repo`'s
  `TranslationCacheRepository`), never on a Room or Android type: `api`, because
  `PersistentCachingTranslationProvider`'s constructor takes one, and the `Room*` implementation stays
  in `:core-model`. Translation no longer leaves the TV for the internet at all -- the line goes to the
  laptop bridge over the LAN (ADR-0005 §2) -- and still degrades when the laptop is off, unpaired or
  slow, which is what the `NoBridge`/`TimedOut`/`Disconnected` split is for. Explanations take the same
  route (`ExplanationCacheRepository`, `BridgeExplainGateway`). `kotlinx-serialization-json` is an
  `implementation` dependency, used only as a JSON tree reader in `Explanation.parse`.
