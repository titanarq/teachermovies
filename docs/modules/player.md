# Module: player

**Gradle path:** `:player`.

## Responsibility
- libVLC Android (stable 3.x) playback of a local file (and later a growing file for stream-while-downloading).
- Hardware decoding, internal/external subtitles, multiple audio tracks, track selection persisted per item.
- Resume from last position; expose position/time as `Flow` for the assistant.
- Hidden EN subtitle mode: the assistant reads cues while the on-screen subtitles stay off.
- `com.teachermovies.player.api`: the `Player` contract and its value types -- `PlayerState` (sealed: `Idle`/`Opening`/`Playing`/`Paused`/`Ended`/`Error`) and `Track(id, name, language)`. State, position, duration, both track lists and both selections are `StateFlow`s; the controls are `open(file, startPositionMs)` (resume is a caller decision, from the position `:core-model` persisted), `play`/`pause`/`togglePlayPause`, `seekTo`/`seekBy`, `selectAudio`/`selectSubtitle`, `addExternalSubtitle(file, select)` and `release`. `com.teachermovies.player.fake.FakePlayer` is the in-memory implementation, with test controls that stand in for what the real player learns from the media (`emitTracks`, `emitPosition`, `emitDuration`, `end`, `fail`).
- `com.teachermovies.player.policy`: pure functions a screen calls to decide what `open`/`selectAudio`/`selectSubtitle` to pass, so that decision is tested independently of any `Player` implementation. `TrackPolicy.audio(tracks, persistedId)` picks the persisted id when it names one of `tracks`, else the first track whose language or name looks English (`en`/`eng`/`english`, case-insensitive, word-bounded), else the first track, else `null` when `tracks` is empty. `TrackPolicy.subtitle(tracks, persistedId)` picks the persisted id when present, else `null` -- subtitles are off by default. `ResumePolicy.startPosition(lastPositionMs, durationMs)` returns `0` when `lastPositionMs` is under 10s or (given a known `durationMs`) within the last 60s of the media, else `lastPositionMs - 3s`.
- `com.teachermovies.player.session`: `PlaybackSession(player, repo: TorrentRepository, scope, clock)` plays one library item. `suspend open(id)` returns `SessionResult` (`Opened(item)` | `NotFound` | `FileMissing(path)`); on success it calls `player.open(file, ResumePolicy.startPosition(lastPositionMs, null))`, adds every `.srt/.ass/.ssa/.vtt` in the movie's folder and its `subs/` subfolder with `addExternalSubtitle(select = false)`, and once audio tracks first appear applies `TrackPolicy` with the persisted ids. It then writes `repo.updatePlayback` every 5 s of `clock` time while playing (checked on position updates), on pause, on a track change and on `suspend close()` (which also releases the player); on `Ended` it stores position 0. Before the tracks are known a save writes back the persisted track ids rather than clearing them.
- `com.teachermovies.player.api.VideoSurfaceHost` is the other half of the contract, split off because only a screen has a window: `attach(view: FrameLayout)` / `detach()`. It takes a plain `FrameLayout`, never the `VLCVideoLayout` libVLC fills it with, which is what keeps `org.videolan` out of `:app-tv`. `FakePlayer` does not implement it; per ADR-0003 `AppContainer` constructs one `VlcPlayer` and exposes it typed as `Player` and as `VideoSurfaceHost`.
- `com.teachermovies.player.vlc.VlcPlayer(context)` is the libVLC implementation of both. `LibVLC` and `MediaPlayer` are created on first use and freed by `release`, so `open` still works afterwards; libVLC reports what the media does on its own native thread, and that thread is what writes the `StateFlow`s -- the listener only reads tracks back, it never calls a control. Its two pure helpers are `internal` and carry no `org.videolan` type: `VlcTrackMapper.map(ids, names)` turns libVLC's two parallel track arrays into `Track`s, guessing the language out of labels like `English [en]` or `Track 2 - [Spanish]` and dropping the `-1` "subtitles off" pseudo-track, and `VlcMediaOptions` holds the `LibVLC` options and the `:start-time` resume option.
- Stream while downloading: `com.teachermovies.player.streaming` holds the pure byte arithmetic, with no engine, player or Android type. `StreamPolicy` (`DEFAULT`: head 2 MiB, tail 1 MiB, start buffer 16 MiB, read-ahead 48 MiB, underrun 2 MiB, resume 12 MiB; `resumeBytes` may not sit below `underrunBytes`) feeds `StreamWindowCalculator` (`byteOffsetFor` at constant bitrate, `windowFor` the read-ahead `ByteRange`, `openRanges` the merged head/start-buffer/tail ranges needed before opening an incomplete file) and `StreamPolicy.decide`, which picks `BufferDecision.Play`/`Wait` with hysteresis and always plays at end of file.
- `com.teachermovies.player.streaming.StreamingPlaybackController(player, engine: TorrentEngine, scope, policy, pollIntervalMs = 500, minWindowMoveBytes = 1 MiB)` sits between a `Player` and a `TorrentEngine` (the one reason `:player` depends on `:torrent`, for its public `api` types only) and supervises playback of a file that is still downloading; `state: StateFlow<StreamState>` is `Idle` | `Preparing(readyBytes, requiredBytes)` | `Streaming` | `Buffering(readyBytes, resumeAtBytes)` | `Failed(reason)`. **What it gates:** `suspend start(id, fileIndex, file, fileSizeBytes, durationMs, startPositionMs): StreamResult` prioritises the first of `openRanges` and polls `rangeReadiness` for every open range each `pollIntervalMs`, publishing `Preparing`; only once all are ready does it call `player.open` + `play` and answer `Opened`. Engine `UnknownTorrent`/`Unsupported` answer at once (the caller may then play unsupervised), `Io` answers `Failed(message)`, `NotReady` keeps polling. **What it prioritises:** while supervising it collects `player.positionMs`/`durationMs` (falling back to the caller's `durationMs` until the media is parsed) and sends `prioritizeWindow` at `windowFor(...)` only when the offset has moved at least `minWindowMoveBytes` since the last accepted call -- a seek is just such a jump, so it costs exactly one call. **When it pauses:** every `pollIntervalMs` it asks `rangeReadiness` for `policy.resumeBytes` at the current byte offset and applies `StreamPolicy.decide` (end of file when offset + `resumeBytes` reaches the file size): `Play -> Wait` pauses the player and publishes `Buffering`, `Wait -> Play` plays it and publishes `Streaming`. A pause it did not cause is the viewer's and is never undone: it stops calling `play()` until the player is `Playing` again. `suspend stop()`, `PlayerState.Ended` and `PlayerState.Error` cancel the loops, call `clearWindow(id)` and publish `Idle` (`Failed(message)` for `Error`); `stop()` on an idle controller is a no-op. A stalled download simply stays in `Buffering`; there is no timeout.

- Embedded subtitle extraction (#115): `Player.extractTextSubtitle(trackId, destination): SubtitleExtraction` writes one embedded text subtitle track of the media currently opened with `open` (an id from `subtitleTracks`) to `destination` as a standalone, timed file. `SubtitleExtraction` (in `api`) is `Extracted(file, format: SubtitleFormat)` (`SRT` | `ASS`) | `TrackNotFound` (nothing open, unknown id, or a track added with `addExternalSubtitle` -- that file is already standalone) | `NotTextBased` (image codecs: `S_HDMV/PGS`, `S_VOBSUB`, `S_DVBSUB`, `S_IMAGE/*`) | `Failed(reason)` (short English reason, never a path other than `destination`). The call never throws and never leaves a partial `destination`: the file is written to a temp file next to it and renamed once every cue is collected. `FakePlayer` answers `TrackNotFound` for an id not in `subtitleTracks`, otherwise what `emitExtractionText(text, format)` (writes `text` to `destination`) or `emitExtraction(result)` configured, and records every call in `extractionCalls`.
- **Supported containers and codecs** (#115, #154). libVLC 3.7.2 has no SRT/ASS muxer and its raw ES dump drops the timestamps, so `:player` holds small pure-Kotlin readers (JDK only: `FileChannel`, `java.util.zip.Inflater`; no `org.videolan` import, no native code):

  | container (detected by) | codec | output |
  |---|---|---|
  | Matroska/WebM (EBML header, DocType `matroska`/`webm`) | `S_TEXT/UTF8` | SRT |
  | | `S_TEXT/WEBVTT` | SRT (cue text kept; cue settings and `STYLE`/`REGION` dropped) |
  | | `S_TEXT/ASS`, `S_TEXT/SSA` | ASS |
  | MP4/M4V/MOV (first box `ftyp`) | `tx3g` (3GPP timed text / mov_text) | SRT |
  | either | image codecs (`S_HDMV/PGS`, `S_VOBSUB`, `S_DVBSUB`, `S_IMAGE/*`; MP4 `subp` tracks) | `NotTextBased` |
  | either | any other subtitle codec (`S_TEXT/USF`, MP4 `wvtt`, `c608`, QuickTime `text`, ...) | `Failed("unsupported subtitle codec ...")` |
  | anything else (AVI, MPEG-TS, ...) | -- | `Failed("container not supported")` |

  `com.teachermovies.player.mkv`: `MatroskaSubtitles.textTracks(file)` checks the EBML DocType (else `NotMatroska`) and lists the `TrackType` 0x11 entries (`TrackNumber`, `CodecID`, `Language`/`LanguageIETF`, `Name`, `CodecPrivate`). `MatroskaSubtitles.extract(file, trackNumber, destination)` walks the Clusters reading only element headers and seeking past every other track's Block/SimpleBlock payload; a cue starts at `(ClusterTimecode + block timecode) * TimecodeScale` and ends after `BlockDuration`, or at the next cue's start (`+5 s` for the last one) without it. Unknown-size Segments/Clusters are handled; a laced subtitle block, a truncated/corrupt file, any content compression other than zlib or header stripping, and any `ContentEncryption` are `Failed`. ASS output is the `CodecPrivate` header, an `[Events]` `Format:` line added when missing, and one `Dialogue:` per block in `ReadOrder` order. `WebVttText` turns WebVTT cue text into SRT text: `<i>`/`<b>`/`<u>` kept (without classes), every other tag (`<v>`, `<c>`, `<ruby>`, `<lang>`, timestamps) dropped with its text kept, character references decoded.

  `com.teachermovies.player.mp4`: `Mp4Subtitles.textTracks(file)` (else `NotMp4`) lists every `trak` whose `hdlr` is `text`/`sbtl`/`subt`/`subp`/`clcp` (`tkhd` `track_ID`, handler, first `stsd` entry type, `mdhd` language). `Mp4Subtitles.extract(file, trackId, destination)` seeks past every top-level box but `moov` (which it loads, up to 64 MiB), then from the track's `stts`, `stsz`/`stz2`, `stsc` and `stco`/`co64` reads only that track's samples; a sample starts at the sum of the earlier `stts` deltas and lasts its own delta, in the `mdhd` timescale, and its text is the 16-bit-length-prefixed UTF-8 (or BOM-marked UTF-16) string -- trailing modifier boxes are ignored and an empty sample (a gap) produces no cue. Edit lists are not applied; a fragmented file (`mvex`), a truncated/corrupt file or a sample past the end of the file are `Failed`.
- `VlcPlayer.extractTextSubtitle` reads the file passed to the current `open` on `Dispatchers.IO` under `extractionTimeout` (constructor parameter, 2 minutes by default; the read is interruptible, so the timeout really stops it) and never touches the playback `MediaPlayer` or its flows. The pure `vlc.EmbeddedSubtitles.extract` sniffs the first bytes (EBML magic vs `ftyp`) and dispatches to the matching reader. The libVLC track id is mapped to a `TrackNumber`/`track_ID` by the pure `MkvTrackMapping.resolve`/`resolveNumber`: libVLC 3's MKV and MP4 demuxers create their subtitle ES in file order when they open the file, using the `TrackNumber`/`track_ID` as the ES id, and an external slave's ES comes after them. So only the first N libVLC subtitle tracks (N = the container's subtitle tracks) count as embedded; among those a numeric id equal to a track number wins, else the n-th maps to the n-th subtitle track of the file.

## Manual verification on the TV
The libVLC track-id mapping on a real file can only be checked on a device (no instrumented tests on the worker host):
1. Play an MKV with an embedded English `S_TEXT/UTF8` (SRT) track; call `extractTextSubtitle` with that track's id from `subtitleTracks`. Expect `Extracted(..., SRT)`.
2. Play an MKV with an embedded `S_TEXT/ASS` track and do the same. Expect `Extracted(..., ASS)`.
3. Play an MKV with an embedded `S_TEXT/WEBVTT` track and do the same. Expect `Extracted(..., SRT)` with no WebVTT tags or cue settings left in it.
4. Play an MP4 (or M4V/MOV) with an embedded English `tx3g` (mov_text) track -- e.g. one muxed with `ffmpeg -i movie.mp4 -i en.srt -map 0 -map 1 -c copy -c:s mov_text -metadata:s:s:0 language=eng out.mp4` -- and call `extractTextSubtitle` with that track's id. Expect `Extracted(..., SRT)`.
5. For each written file, check that it parses with `SubtitleParsers` (`:assistant`) and that its cues line up with the subtitles libVLC shows on screen for the same track (spot-check a few lines early, mid-film and near the end).
6. With an external `.srt` added through `addExternalSubtitle`, calling `extractTextSubtitle` with its id returns `TrackNotFound`; with a PGS track it returns `NotTextBased`.

## Boundaries
- Only this module touches `org.videolan.libvlc` types; exposes a `Player` interface to `app-tv`/`assistant`. Other modules use `FakePlayer` in tests. `libvlc-all` is an `implementation` dependency of `:player` alone, so it is on no consumer's compile classpath and an `org.videolan` import does not compile outside this module.

## Tests
JVM tests for track-selection and resume logic behind the interface (`FakePlayerTest` covers the fake's own behaviour, which is what those tests rest on; `TrackPolicyTest`/`ResumePolicyTest` cover the policies above, table-driven; `PlaybackSessionTest` drives `PlaybackSession` with `FakePlayer`, `InMemoryTorrentRepository` and a `TemporaryFolder`); playback itself is instrumented/manual. `MatroskaSubtitlesTest` builds tiny MKV files in a temp folder with a test-source EBML writer (`EbmlWriter`, no binary fixtures) and covers the track list, exact SRT/ASS timing, content encodings and every failure; `WebVttTextTest` covers the WebVTT-to-SRT cue text; `Mp4SubtitlesTest` builds tiny MP4 files the same way (`Mp4Writer`) and covers the track list, exact timing, gaps, `stz2`, a `co64` table past 4 GiB (sparse file), non-text tracks and truncated files; `EmbeddedSubtitlesTest` covers the container dispatch; `MkvTrackMappingTest` covers the id mapping. `VlcTrackMapperTest` and `VlcMediaOptionsTest` cover the pure parts of the libVLC adapter -- nothing under `src/test` loads `libvlc.so`, so `VlcPlayer` itself is only exercised on a device, by hand.
