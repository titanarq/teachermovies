# Operations runbook -- teachermovies agent OS

How to watch, pause and patch the agent mechanism (`agent_os/`, never edited here) on this host.
Background: `agent_os/docs/AGENT_OS.md` §2.4, §6, §8 and `.claude/agents/control-plane.md` Duty 5.

## Units (systemd --user)

| unit | what | every |
|---|---|---|
| `teachermovies-guard.timer` | `scripts/agent_guard.py tick`: budget/liveness/quota check, writes planner events, wakes the planner | 5 min |
| `teachermovies-board-sync.timer` | `scripts/board_sync.py`: mirrors `status:*` labels to the Project 2 Status column (below) | 5 min |

Unit files for the board sync are versioned in `scripts/systemd/`; the guard's are generated by
`agent-os-install`. After editing any of them: `systemctl --user daemon-reload`.

## Monitor

```sh
systemctl --user list-timers --no-pager | grep teachermovies        # both timers armed?
journalctl --user -u teachermovies-guard.service --since "1 hour ago" -o cat \
  | grep -vE "never started|^0 event|nothing to wake" | tail -40      # tick output
scripts/worker_progress.sh                                           # every backend, last hour
scripts/worker_progress.sh --hours 6 37 qwen                         # one issue / backend
cat .cache/worker_qwen.issue .cache/worker_qwen.state                # what the qwen worker holds
tail -5 .cache/planner/runs.tsv .cache/refiner/runs.tsv              # role runs + cost (USD)
scripts/issues.py list --label status:doing                          # likewise ready/review/blocked-on-human
gh pr list --state open
git -C ../teachermovies-qwen log --oneline -5                        # worker branch commits
```

Qwen reports no cost: report its spend in tokens (`worker_progress.sh`), never as 0 USD.
Alarms: an `EXPECT` past its `cutoff` with no later line; a Qwen issue past ~60 M tokens; a
`blocked-on-human` older than an hour; a timer inactive. Never `cat` a `.jsonl` stage log.

## Pause / resume

- Full stop (the tick returns before doing anything): put `status:agents-paused` on the tracking
  epic #1 -- `scripts/issues.py update 1 --add-label status:agents-paused`; remove it to resume.
  This is the human's lever. A running worker is not killed by it; it is cut at its next check.
- Stop ticking altogether: `systemctl --user disable --now teachermovies-guard.timer`
  (re-arm: `systemctl --user daemon-reload && systemctl --user enable --now teachermovies-guard.timer`).
- Wake the planner early: comment the reason, then `scripts/issues.py update N --add-label wake:planner`.

## Board sync (titanarq/agent-os#14, fixed upstream)

`scripts/board_sync.py` was written because `issues.py move` could not find org project 2's items
(agent-os#14). That is fixed upstream (agent-os PR #26: `move` resolves the item through
`issue.projectItems`; agent-os#23, PR #47: `issues.py create` adds the issue to the board), and
the subtree carries it since the 36985fc pull. The sync is kept for now because it also does what
the mechanism does not: it adds issues created outside `issues.py create` to the board and moves
closed issues to Done. It resolves items through GraphQL `issue.projectItems`, sets Status per
`project.board_columns` (no status label -> Backlog, closed -> Done, `blocked-on-human` -> left as
is), is idempotent and quiet; preview with `scripts/board_sync.py --dry-run`. Retire it (script,
`scripts/systemd/teachermovies-board-sync.*`, the installed unit) once the board is confirmed to
stay in step without it.

The installed unit is a copy: after changing `scripts/systemd/teachermovies-board-sync.*`, copy it
to `~/.config/systemd/user/` and `systemctl --user daemon-reload`.

## CI runners

CI runs on **GitHub-hosted runners** (`runs-on: ubuntu-latest`) since the repo went public
(2026-09-24). The self-hosted runners that used to run it on this machine (`Titan-tm-1..4`) were
deregistered and deleted the same day.

**Rule: self-hosted runners must never be registered for this public repo** -- any fork PR could
run arbitrary code on the machine. The org's Default runner group keeps "Allow public
repositories" **OFF**:

```sh
gh api orgs/titanarq/actions/runner-groups -q '.runner_groups[] | "\(.name) public=\(.allows_public_repositories)"'
```

## Interaction limit

Since going public, the repo has an interaction limit of `collaborators_only` (only collaborators
can open issues/PRs or comment), so outsiders cannot feed text to the agents. It expires after
six months; check and renew it:

```sh
gh api repos/titanarq/teachermovies/interaction-limits
gh api -X PUT repos/titanarq/teachermovies/interaction-limits -f limit=collaborators_only -f expiry=six_months
```

- agent-os#70 "API rate limit already exceeded" with REST quota left -- diagnosed (PR #81): it is

Open, host workaround (to report upstream; regression of agent-os#53, PR #68):
`agent_os/tests/test_no_host_literals.py`'s `test_no_host_literal_anywhere_under_agent_os` and
`test_every_exclusion_still_applies` require a `.git` directly under `agent_os/`, which a
`git subtree` host never has, so they fail in `ci-agent-os.yml` on every mechanism PR. That
workflow `--deselect`s both, commented. `agent-os-install --force` rewrites the file from the
template and drops the deselect: run `git checkout -- .github/workflows/ci-agent-os.yml` after
it. Remove both once fixed upstream and pulled.

`project.install_host_ci` is `false` in `config/agents.yaml`: `ci.yml` already runs
`scripts/test.sh` on every pull request (GitHub-hosted), so `agent-os-install` must not add the
generic `ci-host.yml` (agent-os#50).

Open, host workaround (to report upstream; gap in agent-os#18/#75's fix, PR #20/#80):
`worker_task.sh resume --after manual` after a `DONE` run refuses to relaunch --
"worktree is dirty; commit or clean it first: ?? scratchpad/" -- because
`retire_finished_runs_scratchpad` (`agent_os/bin/worker_task.sh`) only runs on `start`; `resume`
keeps the same run's diary and leaves it out of the dirty check only when the run it continues was
cut by the guard (`drop_the_cut_runs_diary`, agent-os#22), never when it ended `DONE`. `resume
--after manual` is exactly the path the rules prescribe for "changes requested", so this repeats on
every requested-changes relaunch until fixed upstream. Seen on #198's relaunch after the PR #209
review (2026-09-25). Workaround: add `scratchpad/` to the shared `info/exclude` -- one file, the
common `.git/info/exclude` (`git rev-parse --git-common-dir`), covers every worktree of this repo,
worker and lane alike -- so the diary never registers as worktree-dirtying; move any diary already
sitting in a worker worktree out of the way first, e.g.
`mkdir -p .cache/diaries && mv ../teachermovies-qwen/scratchpad/progress.log
.cache/diaries/worker_qwen-issue198-manual.progress.log`. Remove the `info/exclude` entry once
`resume --after manual` archives a finished run's scratchpad the same way `start` does.
